# Deployment Guide

## 1. Run locally (no Docker)

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows   (macOS/Linux: source .venv/bin/activate)
pip install -r requirements-dev.txt
copy .env.example .env            # Windows   (macOS/Linux: cp .env.example .env), then add a key (optional)
uvicorn app.main:app --reload
```
Open http://localhost:8000

## 2. Docker

```bash
docker build -t energywatch-ai .
docker run -p 8000:8000 --env-file .env energywatch-ai
# or
docker compose up --build
```

About the image:
- **Multi-stage build:** dependencies are installed in a builder stage, and the runtime image only contains the virtualenv and `app/`.
- **Non-root user** (`energywatch`, uid 10001).
- **`HEALTHCHECK`** on `/health`.
- **Honours `$PORT`** (needed by Render); defaults to 8000.
- **Single worker** on purpose: the telemetry stores are in memory.

Check it: `python scripts/smoke_test.py http://localhost:8000` (9 checks).

## 3. Render (cloud)

### Option A: Blueprint (recommended)
1. Push the repository to GitHub.
2. Sign in at https://render.com with GitHub.
3. **New + → Blueprint** → choose the repository. Render reads `render.yaml` and creates the
   `energywatch-ai` web service (Docker runtime, free plan, health check `/health`).
4. In the service's **Environment** tab, set `GROQ_API_KEY` (free at https://console.groq.com)
   or `GOOGLE_API_KEY` (free at https://aistudio.google.com). If you set neither, the app runs in
   mock mode.
5. `ADMIN_API_KEY` is generated by Render. Copy it from the Environment tab and paste it in the
   dashboard under ⚙ **Settings** to approve actions and run drills.
6. Wait for the deploy to finish, then open `https://energywatch-ai-xxxx.onrender.com`.

### Option B: Manual web service
New + → **Web Service** → your repo → Runtime **Docker** → Health check path `/health` → add the
environment variables above → Create.

> **Free plan note:** the service sleeps after 15 minutes of inactivity, and the first request
> after that takes about 30-60 s. Open the URL a minute before your demo.

## 3 ter. Hugging Face Spaces

Docker Spaces may require a paid Hugging Face plan. If your account allows them:

**One-time setup (≈ 5 minutes):**
1. Create a free account at https://huggingface.co/join.
2. Create a Space at https://huggingface.co/new-space:
   - Space name: `energywatch-ai`
   - SDK: **Docker** → *Blank* template
   - Hardware: **CPU basic · Free**
   - Visibility: Public
3. Create a token at https://huggingface.co/settings/tokens → *Create new token* → type **Write**.
   Copy it.
4. In the Space → **Settings → Variables and secrets**, add the secrets `GROQ_API_KEY` (optional)
   and `ADMIN_API_KEY` (any password you choose).
5. In the GitHub repo → **Settings → Secrets and variables → Actions**:
   - **Secrets** tab → *New repository secret*: `HF_TOKEN` = the token from step 3
   - **Variables** tab → *New repository variable*: `HF_SPACE` = `<your-hf-username>/energywatch-ai`
6. Re-run the latest workflow (Actions → CI/CD → *Re-run all jobs*), or push any commit.

From then on, every push to `main` that passes the tests is deployed automatically by the
`deploy-huggingface` job. The app is available at
`https://<your-hf-username>-energywatch-ai.hf.space`.

> Free Spaces sleep after 48 h without visits; the first visit wakes them up (≈ 1 min).

## 4. CI/CD with GitHub Actions

`.github/workflows/ci.yml` runs on every push and pull request:

| Job | Steps |
|---|---|
| `test` | ruff lint → pytest with coverage (fails under 85 %) → evaluation benchmark → upload reports |
| `docker` | build the image → run the container → `scripts/smoke_test.py` → print logs |
| `deploy` (push to `main` only) | trigger the Render deploy hook → post-deploy smoke test against the live URL |
| `deploy-huggingface` (push to `main` only) | push the app to the Hugging Face Space → post-deploy smoke test |

Optional configuration (repo → Settings → Secrets and variables → Actions):

| Name | Type | Value |
|---|---|---|
| `RENDER_DEPLOY_HOOK_URL` | Secret | Render → service → Settings → *Deploy Hook* URL |
| `RENDER_SERVICE_URL` | Variable | `https://energywatch-ai-xxxx.onrender.com` |
| `HF_TOKEN` | Secret | Hugging Face token with **Write** access |
| `HF_SPACE` | Variable | `<hf-username>/energywatch-ai` |

Without them, the deploy jobs are skipped with a notice, and Render's own *auto-deploy on push*
still works. If you use the deploy hook, turn auto-deploy off in Render so each commit deploys
only once, after CI passes.

## 5. Configuration reference

| Variable | Default | Description |
|---|---|---|
| `LLM_PROVIDER` | `auto` | `auto`, `groq`, `gemini`, `openai`, `anthropic` or `mock` |
| `LLM_MODEL` | provider default | Override the model name |
| `GROQ_API_KEY` / `GOOGLE_API_KEY` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | - | Provider keys |
| `LLM_TIMEOUT_S` | `20` | Per-call timeout |
| `LLM_MAX_RETRIES` | `2` | Retries per call (exponential backoff) |
| `CIRCUIT_BREAKER_THRESHOLD` | `3` | Consecutive failures before the breaker opens |
| `CIRCUIT_BREAKER_RESET_S` | `30` | Cool-down before the half-open probe |
| `SLO_LATENCY_MS` | `8000` | Latency SLO used by the monitoring agent |
| `ADMIN_API_KEY` | empty | Protects approve/reject/chaos/resolve when set |
| `RATE_LIMIT_PER_MINUTE` | `30` | Per-client limit on `/api/agent/ask` |
| `LOG_LEVEL` | `INFO` | JSON logs on stdout |
| `ENVIRONMENT` | `development` | Shown in the dashboard and `/ready` |
